# H2 Windows psql — інструкція оператора (не дозвіл на запуск)

**Статус: реалізація для незалежного тестування. H2_ROLE_EXISTENCE=UNVERIFIED. LIVE NO-GO.** Цей пакет не підтверджує маршрут, TLS, існування ролі чи право виконати SQL.

1. Встановіть офіційний **PostgreSQL 18 для Windows** (потрібен \`C:\Program Files\PostgreSQL\18\bin\psql.exe\`), PowerShell 7.4+ і Python 3. Нічого не встановлюйте зі скрипта.
2. Завантажте всю папку з **одного перевіреного SHA-коміту**. Не редагуйте \`ROLE_EXISTENCE_PINNED.sql\` чи \`ROUTE_ATTESTATION_TEMPLATE.json\`. З іншої локальної папки виконайте \`python test_offline.py\`; на Windows — \`pwsh -NoProfile -File .\test_windows.ps1\`. Моки не перевіряють реальний TLS.
3. **Жодного виконання в цій задачі.** Для майбутнього одного читання потрібні нова незалежно погоджена атестація project/branch/RO-direct compute/FQDN/port/CA, дата і джерело її SHA-256, окремий рецензент, локальний авторизований оператор і повторне підтвердження власником саме одного read-only запуску. Шаблон має \`false\` і не відкриває виконання. Не використовуйте writer/default/pooled endpoint.
4. **Лише після окремого дозволу** збережіть схвалену атестацію поза репозиторієм, окремо перевірте root CA/hostname і використовуйте команду PowerShell у приватному локальному сеансі. Пароль вводиться лише у власний інтерактивний запит \`psql\`; ніколи не передавайте його в GitHub, chat, CI, env/argv, DSN або receipt. Ім'я облікового запису зафіксовано як \`neondb_owner\`, яке **не є** dedicated inspector і не доводить I1–I7.
5. Команда майбутнього локального запуску, **ЗАРАЗ НЕ ЗАПУСКАТИ**: \`pwsh -NoProfile -File .\Invoke-H2RoleExistence.ps1 -ExecuteOneRead -OperatorName "LocalOperator" -AttestationPath "C:\private\approved-attestation.json" -ReceiptPath "C:\private\one-read-receipt.json"\`. Лише один процес, без повтору після помилки. \`sslmode=verify-full\`, \`sslrootcert=system\`, 5 s connect, 20 s wall; використовується тільки зафіксований SQL із явним ROLLBACK. Сертифікати, root CA, route і один physical session потрібно перевірити незалежно поза моками.
6. Receipt має бути поза Git, максимум 8192 байт, без секретів. Перед передачею рецензенту: \`python verify_receipt.py C:\private\one-read-receipt.json\`; рецензент перевіряє оригінальний readback, провенанс маршруту/порту/CA, identity/TLS, один зв'язок та rollback. Сам output-парсер не може підтвердити фактичну кількість sessions або автентичність TLS. Не викладайте в CI/Git необроблений transcript, DSN, паролі або мережеві дані.
7. Якщо будь-яка перевірка не пройшла, результат **UNVERIFIED**, немає повтору, немає fallback, немає provisioning. TRUE/FALSE з mock не означають роль у Neon.

Поточні файли призначені спочатку для Git publication та ізольованої Windows-перевірки. Немає дозволу на Neon API, live SQL, production, WIP або provision.
