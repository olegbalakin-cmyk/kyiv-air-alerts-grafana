## What is implemented

- The existing Kyiv city UI gets a separate read-only card under the KPI cards, visible only while the City selector is `kyiv`.
- This card displays **24 provisional start records**, their exported estimated ends, 4-day count and time, with explicit caveats in Ukrainian and English.
- Source CSV hashes and approximate-end provenance are committed to the independent static file `kyiv-air-alerts-grafana/pages-preview/kyiv-early-2022-preview.json`.
- The UI reads ONLY this sidecar. The canonical `dashboard_data.json`, `alerts_combined.json`, `historical-daily-kpi.json`, `site_derived.json`, `kyiv_threat_mix.json`, and Neon writer are untouched. The existing 23-city dashboard remains canonical. No approximation enters historical KPI, forecasts, city comparisons, or cumulative historical hours.
- A branch-local `netlify.toml` test-build edit includes the two new static assets. **This research branch must NOT be merged or deployed to production without a separate review, build, and owner release authorization.**
- Localized UA/EN labels are provided from the same DOM and script, with source link to `https://blog.alerts.in.ua/p/data-sources`.
- Daily estimated time is unioned across overlapping intervals and split at Kyiv local midnight (February 2022 UTC+02:00), so the 27 February alert's 23m36s estimated spillover into 28 February is shown separately.

## Static build and scheduled update separation

The production C6 writer `scripts/c6_neon_auto_git.py` defines `DELIVERED` from six canonical C2 output files, and its `allowed()` allowlist targets `kyiv-air-alerts-grafana/data/` plus Grafana data. Its static JSON remains versioned in the research branch and is not regenerated by the four-hour updater. The real production publisher is unchanged; a **physical scheduled-cycle proof** after deployment would still be required before closing the integration release gate.

Netlify's existing published build uses explicit `cp` commands. The research branch adds the two static preview assets to that copy list to make a branch/test build possible; it does not change `site-prod` by itself.
